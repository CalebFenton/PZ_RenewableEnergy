# Structural mechanism audit

## Purpose and selection rule

This audit supersedes the adjacent-helper-first priority in [the consolidation plan](consolidation-plan.md), not its preservation gates or completed work. The user asked for ambitious structural simplification, landed incrementally, rather than a succession of small optimizations.

Baseline: 17,148 physical lines of shipped RE Lua and 23,344 of RE-specific development Lua, excluding commonlib and the shared harness. These include comments, blanks and definitions; they are not executable-line counts or an estimate of removable code. Start with production mechanisms, not generated data or the harness simply because those files are large.

For each candidate, identify: the complete operation and its entry points; the owner of each state representation; duplicated implementations or compensating machinery; the exact machinery a cutover deletes; differences that must survive; native capability; and the runtime experiment that can reject the design. A file move, shorter helper or new generic framework is not an architectural result. Rank deletion of entire mechanisms above repeated-call savings. Record negative findings so the next session does not rediscover rejected shortcuts.

## Re-ranked teardown audit

The first passes traced RE development code, RE/commonlib jobs and device lifecycles, and equivalent RE/EI/HA mechanisms. A subsequent shipped-code pass traced native callback wrappers, vehicle charging, fluid plumbing/transfer and common material/learning integration. It established three mod-owned failures below, not a large removable production framework. Rank the demonstrated ownership problems ahead of the deferred loot-analysis work.

The inventories below count **existing physical lines at audit time**, including comments/blanks, not net savings. Replacement code is still needed. The investigation probes were removed; subsequent production fixes and retained regressions are recorded under each finding.

**Priority correction after user review:** native delegation is not native conformance testing. Production code should let the engine own its mechanics; permanent checks should exercise mod-owned decisions, state changes and integration outcomes, not independently certify native probabilities, timers or other engine algorithms. A small discriminating probe is justified for an unclear API contract; retain a focused integration regression only when it protects a concrete mod dependency. The removed T1 probes answered a measurement-tool assumption, not whether the game's probability engine is correct. Loot reports are optional balance-analysis tools, not tests; their existence does not make statistical validation the next consolidation priority. T1 is deferred as the main mission. Do not expand sampling or build probability tolerances merely to justify deleting its estimator.

### P1. Irrigation: one water owner, and one truthful delivery result

**Problem in plain terms:** the mod sometimes installs its own water supply without disconnecting vanilla's. Separately, its transfer adapter says water moved when it did not. These are shipped behavior failures, not native-conformance findings.

**Fixed fixture ownership.** EI `server/EnhancedIrrigation/Fixtures/FixtureSystem.lua:27-41` now disables external routing before returning an existing buffer. Both explicit plumbing and save conversion use that owner. Unplumb legitimately retains buffers, and native Plumb can re-enable rooftop routing; allocation-once must not mean takeover-once. New-buffer creation/sync and reserve escrow remain unchanged.

**Real SP reproduction:** placed an empty buffered sink under a 50 L tainted rooftop tank, ran native `ISPlumbItem.complete`, then the real `FixtureSystem.convert`, then drew 1 L through the sink into a real bucket. Conversion reported finished and created an EI link, but `external=true`. Its buffer held **20 L before AND after** the draw, the rooftop source lost **1 L**, and the bucket was **not tainted**. EI had filled a hidden buffer while native routing still served/purified water. The probe exercised completion/conversion/draw directly; it did not drive the menu, the full Unplumb/replumb sequence, chunk reload or MP replication.

**Transfer failure before the fix.** EI `shared/EnhancedIrrigation/Links/Links.lua:60-67` called void `FluidContainer.Transfer` and unconditionally returned true after amount checks. Its consumers are tank equalization (`server/.../Links/LinkSystem.lua:153-175`), fixture fill (`FixtureSystem.lua:79-84`) and treatment drainage (`server/.../Treatment/TreatmentObject.lua:89-115`). In the SP probe, requesting 2 L from 5 L Petrol into 1 L Water returned **true**, with source still **5 L** and destination still **1 L**.

**Fixed delivery accounting.** `Links.carry` now checks native `FluidContainer.CanTransfer`; native transfer still owns admissibility and mixing. `PumpWater.draw` now measures destination amount change instead of trusting `IsoObject.transferFluidTo`'s attempted amount, for both object and natural-water sources. Its no-container garden-line path is unchanged. The native finite-container transfer already syncs its source; the duplicate sync is gone. Boolean and litre-returning contracts stay distinct, without a new transfer abstraction or caller migration.

**Wear callers checked.** Hand pumps pass the accepted litres to `record:lift`; rejected delivery now leaves seal and body wear unchanged. The retained real-game regression locks an actual outlet, checks `Links.carry` returns false, then runs half an hour of actual hand-pump work and checks unchanged source, destination and wear. Pump Houses intentionally wear by running time even when an outlet takes nothing; do not reinterpret a blocked outlet as a dry source.

**Deletion accounting.** EI `562bb7c` removes **2 net production Lua lines** and adds **32 net development Lua lines**. Buffer takeover is a zero-line reorder; native admission adds no lines; accepted-delivery measurement replaces optimistic results and redundant sync. Selected/rate-limited/taint-preserving plumbing, held reserves and pipe refunds remain. This is a correctness/ownership fix, not a large teardown.

**Runtime evidence.** The coherent batch passed **21 SP and 21 MP scenarios**, with one platform-specific skip in each. Coverage includes first plumbing, retained-buffer conversion on SP chunk load and explicit MP conversion/client flags, native-menu taint, Unplumb refunds, town-water precedence, finite-source depletion, tank equalization, treatment drainage, rejected delivery/hand-pump wear and existing powered-pump wet/dry policies. 148/148 Lua compilation, cross-checks and dedicated-server startup passed.

**Evidence limits.** The earlier direct native-Plumb → convert → bucket probe demonstrated the failure; the retained conversion regressions start from a buffered, externally plumbed fixture. A full Unplumb → native-menu Plumb → convert sequence in one scenario and a full process save/restart were not run. MP evidence covers explicit conversion/client state, not a dedicated server's first chunk-load hook.

### P2. Vehicle charging: adjust the input, not an already-clamped result

**Operation before the fix:** RE `server/RenewableEnergy/Gadgets/VehicleBatteryCharging.lua` saved battery charge, called vanilla, measured the increase, scaled it for capacity/removed alternator, rewrote charge and could resend it. Vanilla `Vehicles.Update.Battery` had already clamped and rounded the charge (`lua/server/Vehicles/Vehicles.lua:505-523`). The mod cannot recover the original offered energy from that saturated difference.

**Real SP reproduction before the fix:** the existing authority `alternatorCharge` handler put a deep-cycle battery at **0.99**, repaired/fuelled and started a real vehicle, then invoked the production battery update for **60 elapsed minutes** in one call. Enough alternator input exists to fill the last 1%, but final charge was **0.9947599768638611**. The mod scaled remaining headroom rather than offered input. No minute was waited out. The ordinary capacity test starts at 0.2; a retained near-full case now protects the saturation boundary.

**Fixed boundary:** for a running engine, the captured vanilla battery update receives capacity-scaled elapsed input (zero when its alternator is out); otherwise it receives the original input. Native charging, clamping, quantization and publication happen once. Native Lightbar processing still runs; it drains only while the engine is off (`Vehicles.lua:626-653`), where the existing chargeBattery adapter already scales its delta. No copied alternator rate or saved remainder is needed.

**Deletion accounting:** RE `8879d2c` removes **15 net production Lua lines** and adds **8 net development Lua lines**. The before/after calculation, corrective charge write, resend and unused Battery import are gone. The discharge adapter remains. Both fixes together remove **17 production Lua lines**, with **40 development Lua lines added**; total Lua therefore grows by 23 lines. These are bounded correctness/owner fixes, not large-scale code removal.

**Runtime evidence:** **5/5 SP and 5/5 MP** affected scenarios passed: ordinary and near-full charging, removed/reinstalled alternator, headlight drain and engine-off lightbar drain. Each capacity scenario uses both vanilla and deep-cycle batteries. The near-full case starts the client's battery at 0.99 and waits for its actual charge to reach 1, so an unchanged initially-full client copy cannot pass. Final compilation covered 209/209 Lua files with all cross-checks; dedicated-server startup passed. No full process save/restart or other-mod wrapper composition was exercised.

## Earlier cutovers and capability gates

### M1. Complete initial publication instead of publish-then-resync

**Structural target:** delete the bank-added client listener/request in `client/.../PowerBank/ClientBankSystem.lua:26-37` and the server `resync` command branch in `server/.../PowerBank/BankSystem.lua:232-236`. Construction should make the first published bank semantically complete, including restored active records, instead of requiring a second client/server exchange. The native full-object serialization already includes the generator flags, fuel and condition. However, the setters send separate reliable-unordered SyncIsoObject snapshots, while the object itself uses ordered AddItemToMap publication. A state packet can arrive before its object. A reconstructed bank can also reactivate during `Bank:loaded -> refresh -> switchGenerator`, after the initial setters.

**Real MP probe, 2026-10-26:** instrumented the existing `renewable_energy_world_bank_spawns_stocked` scenario without replacing production construction or its repair protocol. All three bank tiers first reached OnObjectAdded as **connected=false, fuel=0, condition=0**. At validation all three were **connected=true, fuel=10, condition=100**; the existing scenario passed. **Native feasibility result:** `IsoGenerator(IsoCell)` is detached; `setInfoFromItem` initializes fuel/condition without sending, but not connection/activation. `setConnected`, `setActivated`, `setFuel` and `setCondition` send state. Calling sync-producing setters without a square/object index logs errors. No legitimate atomic no-send connection/activation initializer was established.

**Status: blocked for deletion, not approved for a setter-reordering patch.** Moving setters before publication can leave older intermediate snapshots arriving after the final object; suppressing packets globally, debug reflection, or hand-building native serialized/network state would replace a small workaround with more fragile machinery. Keep resync until a supported initialization contract covers final flags AND restored-record reconciliation. The source evidence is in installed `IsoGenerator`, `IsoObject.syncIsoObject`, and `LuaJavaClassExposer`; the first-copy evidence is from the real MP run above.

**Acceptance if unblocked:** observe first client availability, not just eventual convergence, for new stocked banks, player-placed tiles and rebuilt active banks. Verify initial stock/flags, restored charge/wear, power/toxicity, overlays and later normal switching in SP/MP. Remove the whole request/response path and its documentation together. This remains a blocked lifecycle-deletion lead, not a promised line reduction or the current next cutover.

### M2. One source-change operation across player jobs and world wiring

**Completed.** Existing owner: JobSites plus Bank's attachment/removal mutations. This removes duplicated orchestration; it is not a measured performance improvement or a large code reduction.

Disconnect entered `BankSystem.dropSource`, which updated/removed/published; source.tell published again. Standalone BankSystem.dropSource remains for destruction and treadmill unwiring. Compare current world-versus-player preparation order before merging them: connection helpers must not change billing/backup results incidentally.

**Ordering decision:** player jobs retain destination-then-previous preparation. The only production caller of the standalone connect entry point is SolarSites wiring a newly placed wind charger, with no previous bank; it has no two-bank preparation order to reverse. Same-bank preparation/publication is deduplicated. Catch-up can still send its own elapsed-state updates; the cutover does not suppress simulation notifications.

**Exercised evidence:** the source-family batch passed **97/97 SP** and **98/98 MP**, with leak checking enabled. The new permanent `renewable_energy_bank_source_transfer_settles_both_ends` regression verifies old-topology production credit, both watched banks' final state, and production credited to the destination only after transfer. Existing cases exercised same-bank reconnect, catch-up-invalidated source refusal, pending treadmill energy on unwire/pickup, connection XP, partial bulk success, sealing/brakes/blades and named-site world wiring. The extra MP case removed a real destination controller and set its record clock to now immediately before authority job completion, in the same Lua call: the connection was refused for lack of slots and the client received the recounted destination summary. That temporary probe and its server branch were removed. No benchmark or duplicate-scan reduction is claimed.

**Code accounting:** JobSites.lua is 304 lines versus 298 before this cutover (**+6 production Lua**); the retained two-bank regression adds **39 development Lua lines**. No files were moved. ## Mechanisms retained on purpose

- **Digester hopper and eaten:** one describes simulated remaining feed, the other unapplied deductions against real inventory IDs/uses. The loaded/unloaded feed algorithm was already unified. Removing either requires a different resource contract, not a table cleanup.
- **Bank battery and part wear debt:** cycle wear is nonlinear and ordered; part wear has different rules. Saved load and charger demand have live unloaded/allocation consumers. Summing/deleting these changes behavior.
- **Gasifier loaded-only inventory access:** unloaded gasifiers burn their existing fire but do not stoke or consume filter inventory. A digester-style generic snapshot system would add behavior.
- **Global summary versus watcher status:** globally synchronized rounded device summaries and detailed bank-window state serve different consumers and costs. Do not replace both with an always-broadcast universal payload.
- **Saved world ledgers:** site-name rolls, rural claims, empty failed outcomes, garden true-versus-number promises, and trailer stock markers preserve save compatibility and prevent respawn after player removal. Native object scans cannot replace that history.
- **Separate readiness contracts:** room loot, surrounding-ground building rolls and durable named-site placement have different triggers and retry rules. A shared scheduler is not justified just because all three place objects.
- **ArrowBoard correction:** native addVehicleDebug and world-story constructors overwrite part conditions after addToWorld/OnSpawnVehicleEnd. The installed item is overwritten too. Keep the saved original condition and next-tick correction until a genuinely later native hook is established.
